# DB6 EMG audit (2026-10-25)

## Scope and evidence

The repository was inspected before algorithm changes. The DB6 subject-1
extraction is present under `data/db6_subject`; it contains ten sessions
(`S1_D1_T1` through `S1_D5_T2`). The working tree was already dirty with
untracked DB6 data and experiment scripts; those files were preserved.

The existing commands were run unchanged with the repository's Python 3.13
environment (`numpy 2.4.6`, `scipy 1.17.1`, `scikit-learn 1.9.0`):

```text
python experiments\db6\db6_baseline.py --dir data\db6_subject --out data\db6_subject\baseline_reproduced_20261025
python experiments\db6\db6_step3c.py --dir data\db6_subject --out data\db6_subject\step3c_reproduced_20261025 --skip-matrix --boot 200
```

Both runs completed successfully. The baseline run found ten `.mat` files,
used channels `[0, 1, 2, 3, 4, 5, 6, 7, 10, 11, 12, 13, 14, 15]`, and
retained 6,784--6,838 windows per session. Labels were rest (`0`) plus seven
grasp classes (`1, 3, 4, 6, 9, 10, 11`). Training used repetitions 1--8 of
`S1_D1_T1`; its held-out test used repetitions 9--12. Other sessions were
evaluated using all repetitions for the time-gap curve.

## Reproduced results

| Evaluation | Accuracy | Balanced accuracy | Notes |
|---|---:|---:|---|
| Cross-session baseline mean | 55.5% | 48.7% | Mean over the nine sessions not used for training |
| Cross-session Fix B mean | 60.1% | 54.2% | Per-target-session feature z-score |
| Same-session baseline, `S1_D1_T1` held-out reps | 70.1% | 65.9% | Ceiling-style reference |

Fix B is an offline target-session transform: its mean and standard deviation
are fitted using every target-session window, including windows later reported
as test results. It does not use labels for the z-score itself, but it uses
future target-session samples and is therefore not an online causal result.
Its performance is also sensitive to the target session's unlabeled
grasp/rest mixture. `B_rest`, `B_train`, `B_causal`, and `B_roll` are available
as protocol comparisons; they should not be collapsed into the Fix B claim.

## Confirmed implementation/protocol risks

1. **Target-session calibration scope is broader than the test split.** `B`
   fits statistics from all target windows. This is permissible only when
   explicitly described as transductive unlabeled calibration; it must not be
   presented as a leakage-free online result.
2. **Window metadata can cross repetition/object boundaries.** The current
   baseline and Fix B window builders retain windows when the gesture label is
   constant, but select repetition/object metadata by majority vote. A
   constant-label window spanning a repetition or object boundary can
   therefore be assigned to one side while containing samples from both. The
   window contract should require constant label, repetition, and object.
3. **Filter state is reset for every session.** `sosfilt` is causal, which is
   appropriate for streaming, but resetting state at each file creates a
   startup transient. The transient policy is undocumented in the output and
   should be made explicit/tested; a streaming implementation needs persistent
   SOS state.
4. **Feature thresholds are protocol-sensitive.** ZC/SSC thresholds are
   frozen from the training session in the baseline/Fix B path, which is
   appropriate for a deployable classifier. The alternative drift script uses
   a different threshold ratio and a different SSC condition, so its results
   are not directly interchangeable with the baseline.
5. **Cross-subject evidence is absent.** Only subject 1 is available in the
   current DB6 directory. No cross-subject claim is justified by the present
   evidence.

## Not confirmed as bugs

- Rest windows are retained in the current v2/Fix B pipeline: every session
  has substantial rest counts in both train and test splits.
- The textbook ZC and SSC feature ordering is present in the current baseline
  and Fix B implementations; synthetic regression tests are still needed to
  protect it.
- The training threshold is not fitted from test labels. The main remaining
  concern is calibration scope, not label leakage.
- The split has matching object IDs in train and test for all ten available
  sessions, so no object-confounding warning occurred in the reproduced run.

## Initial change boundary

The next changes will be surgical: add synthetic regression tests, tighten
window-boundary validation, expose protocol metadata, and add separate
hardware-readiness documentation. Existing experiment history and raw data
will not be moved, deleted, or rewritten.

## Changes and validation

The window builders now require label, repetition, and object metadata to be
constant across every retained window. The alternate drift pipeline also
rejects windows spanning an object boundary. Six synthetic regression tests
cover rest retention, boundary alignment, ZC/SSC hand-checks, threshold
behavior, train-only normalization, and constant-feature normalization.
